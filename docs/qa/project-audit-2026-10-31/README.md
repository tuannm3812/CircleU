# CircleU project audit

31 October 2026. CircleU has a useful native foundation and a coherent new visual direction. The main problem is integration: the current Figma prototype, guest review app and standard Release are different products at different stages. A new backend or broad rewrite is not the next step.

This audit covers product decisions, documentation, the current Figma page, asset packaging, guest architecture and persistence, legacy Firebase rules and recovery, AI boundaries, build configuration and tests. It is a source and prototype review with fresh local verification, not a certification of every screen, deployed Firebase rule or release archive.

Baseline: `9967a1057310c84e569c8ffecc434a3c7db905c9`, branch `codex/app-upgrade-plan`. Before adding this report, the working tree contained 26 modified tracked files (1,227 insertions / 297 deletions) and 356 untracked files totalling approximately 91 MB. Findings refer to that working tree. Application code, cloud configuration and Figma designs were not changed during the audit.

Several UI tests deliberately collect accessibility findings with `try? performAccessibilityAudit` and a handler that returns `true` for every issue (for example `GuestPolishUITests.swift:9`). These are informational attachments, not a failing accessibility gate. Passing UI tests must not be described as a clean accessibility audit. Triage their attachments and keep explicit hardware VoiceOver qualification.

The text-attachment helper in `GuestUITestSupport.swift:7` does not set `.keepAlways` (screenshot helpers do). Exporting `*.txt` from this successful UI result returned no matching attachments, so it supplied no retained accessibility findings to triage. Make text retention explicit and distinguish known accepted audit issues from unexpected audit failures in the next QA cleanup. The absence of exported text is not proof that the screens had no issues.

The member lookup at `firestore.rules:76` also uses `{circleID}` inside `get(...)`, instead of interpolating the matched variable with `$(circleID)`. Correct and compile-test that lookup before relying on member-gated post creation. Firebase documents the required path interpolation in its [rule conditions guide](https://firebase.google.com/docs/firestore/security/rules-conditions). No emulator compiler result is claimed here.

The existing feature folders, ViewModels and service protocols already provide a practical MVVM-style separation. Preserve them. The guest store is substantially more defensive than a simple demo store: it rejects stale writes, keeps unreadable drafts visible as failures, separates original words from suggestions and disables CloudKit for this store. Splitting everything into a new architecture would delay the UI work without resolving the specific findings above.

Git currently lists nine checkouts/worktrees. The original `Documents/GitHub/3. Personal/CircleU` folder is on `main` at the same base commit, but does not contain this worktree's pending app/design changes; its status only showed two untracked handoff notes. This can explain why opening the original project shows an older experience. Use the documented current worktree and **CircleU Guest Review** for local native review until changes are integrated. Audit and preserve each worktree before any later cleanup; none was removed or reset.

The project still targets iOS 17 and includes iPhone/iPad build support. This audit exercised one iPhone Simulator on iOS 27, not that entire compatibility range. Qualify a small-screen phone, the chosen minimum OS, a phone without available Apple Intelligence, large text and the actual showcase device against the [device plan](../../product/supported-devices.md). Changing the deployment target or dropping iPad is a separate release decision.

## Figma and visual review

[Current prototype](https://www.figma.com/proto/rfknpmLIXsOxA7fHUQQMtR/CircleU-Design--from-Claude-canvas-?node-id=74-3&starting-point-node-id=74%3A3): page `74:2`, **CircleU • current prototype**. Read-only structural inspection found 7,263 descendant nodes and 1,669 direct node-navigation actions, with no missing referenced destinations. Conditional action branches were not recursively audited. An existing destination does not prove that a button chooses the correct state or preserves input; this was not a complete player regression.

All six `Scene artwork` instances are 342 × 171. The scene family has Window pause, Reflection garden and Voice corner variants, so artwork can change without rebuilding each screen. Font segments on the current page use Plus Jakarta Sans Regular/SemiBold; headings are commonly 24, body content 15–17 and small metadata 11–13. Native `GuestBrand` bundles Plus Jakarta Sans with its SIL license and scales text with Dynamic Type.

Visual feedback, based on the saved Today review-21 and Journal review-15 captures plus current structure:

- Keep the current Today composition. The illustration, editor, small prompt selector and single Save action are much clearer than adding another instruction card.
- Keep context and feeling visually different: a compact context chip on the left and an expressive Pingu portrait with a label on the right. Do not shrink the tap area with the artwork. Missing tags should stay optional.
- Use a short typography role table to reconcile Figma and native sizes. Do not reduce all text to make it fit; keep metadata secondary and preserve large-text reflow.
- Reuse the scene component for intentional refreshes. Automatic/random scene rotation is not implemented or needed for this review.
- Complete the stale-reflection branch and a bounded Today → save → Journal → edit → Practice → reply walkthrough before producing final showcase screenshots.

Figma remains a fixture-based interaction prototype, not proof of real keyboard behavior, arbitrary typing, voice recognition, durable saving, model quality or accessibility. Earlier pages and review frames are historical options; the named current page should be the entry point.

## Assets and privacy

- Checked all 86 `Circleu/Assets.xcassets/**/Contents.json` manifests: no missing referenced image/data files and no unassigned PNG/JPEG/PDF/SVG files in those catalog directories. This does not prove every dynamic image name or visual crop is correct.
- Latest scene and transparent emotion originals are stored in the prototype's `Resources/BrandArtwork` library; native catalog adoption is only partial. Keep that distinction in the asset manifest instead of treating every generated file as shipped art.
- The app has `PrivacyInfo.xcprivacy`, including UserDefaults and other required-reason declarations; a missing-manifest finding is not warranted. Its collection declarations cover the legacy app. Reconcile the eventual guest release manifest and App Store disclosures against its actual network behavior and dependencies. Apple's [required-reason guidance](https://developer.apple.com/documentation/technotes/tn3183-adding-required-reason-api-entries-to-your-privacy-manifest) is a release reference, not evidence of App Store acceptance.
- Guest dictation requires on-device Speech and does not write an audio recording file. Optional Firebase recovery is a distinct networked action. Source isolation does not replace an observed offline/network test of the exact distribution build.
- The [Firebase rules assessment](firebase-rules-audit.json) scores the repository rules only. It contains no user data, credentials or deployed-state assertion.

For the showcase, [poster refinement 06](../../design/showcase-2026-10-30/refinement-06/README.md) has a 2560 × 1440 PNG and editable single-slide PowerPoint. Its phone screens and wordmark are raster artwork with illustrative generated text, rather than exact current screenshots. The prior cloud poster and six-slide deck were not updated by that revision. Use exact approved screen exports for the next mockup pass, check PowerPoint font substitution, and synchronise the poster and deck before sharing. The existing simple MP4s are optional artwork previews, not a required showcase video.

## Recommended order

1. **Preserve and stabilise:** review/checkpoint the pending work; repair and test the reflection decoder; record the cloud rule issues separately so they are not lost while UI work continues.
2. **Finish the design contract:** reconcile brief/stories/status, close the stale-reflection Figma branch, and review the short cross-tab journey. Keep circles and new cloud AI deferred.
3. **Bring one approved flow into native:** start with the approved Today composer/question picker and current Journal tag hierarchy, reusing the existing ViewModels and assets. Prototype approval alone is not native implementation authorization.
4. **Polish the showcase:** refresh poster mockups from that approved visual baseline, settle type hierarchy and prepare concise slides. Do not add a video requirement or imply an unavailable App Store download.
5. **Qualify the private beta:** resolve release identity and legacy recovery, validate rules, run unit/UI and physical checks on the actual build, then verify the invitation/QR destination.

Immediate recommendation: a small reliability-and-documentation cleanup, followed by the approved Today/Journal visual integration. Do not start a new server or rebuild the whole application.
